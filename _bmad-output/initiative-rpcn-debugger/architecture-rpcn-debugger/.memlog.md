- (constraint) [ADOPTED] Session model is capture-then-step: run only the input, take ONE batch, never ack (nack), stop the input, then step that batch through the processors. Proven with the redpanda input: no offsets are committed, and reruns restart from offset 0
- (constraint) [ADOPTED] Uses only the public API: benthos/v4/public/service + connect/v4/public/components/*; no engine fork or patch
- (constraint) [ADOPTED] Stepping goes through a registered batch-processor plugin (rpcn_debug_stepper) that wraps each processor list, built via NewProcessorListField -> []*OwnedProcessor. Standalone ConfigSpec.ParseYAML is forbidden, because it can't resolve resource: processors
- (constraint) Plugin names must match ^[a-z0-9]+(_[a-z0-9]+)*$
- (constraint) [ADOPTED] The YAML rewrite wraps the child lists of branch, switch cases, try, catch, for_each, while, workflow.branches.*, parallel, group_by groups and retry. The stepper carries path + per-child YAML lines. Modes: all (ExecuteAll) and try (ExecuteTryAll). Equivalence with/without the debugger was proven on all of them
- (constraint) [ADOPTED] Concurrency (workflow layers, parallel, retry parallel:true) is handled by a global pause gate held only while paused, never while a processor runs; this avoids nested deadlocks
- (constraint) Batch size: the redpanda input has no batching field, and broker batching doesn't split a fetch, so the debugger enforces maxMessages itself by truncating
- (constraint) group_by splits and reorders messages into several batches, so the step state model is a list of batches, not a flat message list. retry re-enters the stepper on each attempt (the debugger counts attempts). try/catch/for_each/parallel/retry run once per message
- (constraint) Display: []byte metadata such as kafka_key is rendered as UTF-8; __-prefixed internal metadata is hidden or grouped; engine log paths are translated from the rewritten path back to the user's path; Bloblang error lines are offset by the YAML line of the mapping
